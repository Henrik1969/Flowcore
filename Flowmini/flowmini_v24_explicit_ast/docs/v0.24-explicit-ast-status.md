# Flowmini v0.24 Explicit AST Status

Status: active development branch  
Branch theme: explicit AST stabilization  
Implementation maturity: partial, observable, regression-guarded

## Purpose of v0.24

The v0.24 Flowmini line exists to make the AST explicit and trustworthy.

Earlier work made lexer and TokenTree behavior observable. v0.24 moves the project toward a first-class AST layer.

The guiding distinction is:

```text
TokenTree remembers what the source looked like.
AST states what the source means.

Or, in the current architecture stack:

Lexer
    Here are the words/symbols.

TokenTree
    Here are the words/symbols grouped by source structure.

Flowmini AST
    Here is what the program says.

Semantic checker
    Here is whether what it says is legal.

SymbolTable
    Here are the named facts/scopes/contracts.

Graph IR
    Here is the executable/source architecture as nodes, ports, wires.

Lowerer/runtime
    Here is how we actually make it run.
Current AST guarantees

v0.24 currently provides an observable AST dump path:

./cmake-build-debug/flowmini --dump-ast <file.flow>

The AST currently covers:

source unit header
top-level function shells
top-level main block shell
imports
records
type aliases
function parameters
function return type shells
function/main body containers
return/break/continue statement shells
typed binding statement shells
plain assignment statement shells
if/while statement shells
nested if/while body statement shells
expression presence markers
expression placeholder IDs
expression pool dump
identifier/literal expression atoms
call-expression recognition
shallow binary/unary operator expressions
shallow index/field-access expressions
shallow list/record literal placeholders
What the AST does not yet guarantee

The v0.24 AST is not yet a full semantic or executable language model.

The following are intentionally incomplete or deferred:

deep expression trees
operator precedence trees
call argument AST nodes
binary expression operands
unary expression operands
index argument AST nodes
field-access chains
list literal elements
record literal fields
else blocks
full type-reference parsing
semantic name resolution
symbol table integration
type checking
graph IR lowering
runtime execution semantics
provider/capability resolution

The current expression support is deliberately shallow.

Example:

x + 1

may be recognized as a binary expression with operator "+", but v0.24 does not yet build a complete operand tree.

This is intentional.

v0.24 follows the rule:

First existence.
Then visibility.
Then population.
Then dependency.
Golden AST regression tests

The canonical AST source examples live in:

examples/ast/*_probe.flow

The expected normalized AST JSON outputs live in:

tests/expected/ast/*.ast.json

The golden AST test runner is:

tools/run-flowmini-ast-golden-tests.sh

The CMake target is:

cmake --build cmake-build-debug --target flowmini_ast_golden_tests

The expected result is:

AST golden tests: PASS (8)

The full Flowmini suite remains:

cmake --build cmake-build-debug --target flowmini_suite

Expected result:

total: 76
pass:  76
bad:   0
Golden update mode

When AST output changes intentionally, update goldens with:

FLOWMINI_UPDATE_AST_GOLDENS=1 tools/run-flowmini-ast-golden-tests.sh

Then inspect the diff before committing:

git diff -- tests/expected/ast/

Golden files should only be updated intentionally.

The design law is:

If v0.24 AST behavior changes,
the golden AST tests must either fail
or the expected AST files must be intentionally updated.
Example directory warning

The examples/ast/ directory may contain both canonical probes and exploratory edgecase files.

Do not blindly treat every file in examples/ast/ as part of the golden regression gate.

The checked-in expected files define the canonical golden test set.

See:

examples/ast/README.md
Current main rule

v0.24 supports exactly one root main block in a root program.

Multiple root main blocks are currently an error.

Future Flowmini/Flowcore may support multiple named buildable or runnable targets from the same source base using a model like:

program toolset

target cli {
    main {
        ...
    }
}

target daemon {
    main {
        ...
    }
}

That future direction is documented in:

docs/language/named-targets.md

It is not implemented in v0.24.

v0.24 development law

The AST is now observable and regression-guarded.

Before deepening the AST, keep the following true:

build is green
flowmini_suite is green
flowmini_ast_golden_tests is green
golden diffs are intentional

The current line is allowed to be incomplete.

It is not allowed to be vague.
