# Recovered TinyVM dispatch baseline — 2026-08-26

These are exploratory observations, not controlled performance claims. The
machine was running an ordinary graphical desktop, CPU affinity and frequency
were not fixed, and each reported row is one timed sample after a short warmup.

## Host

- CPU: Intel Core i5-13600KF, 14 cores / 20 logical CPUs
- Architecture: x86-64
- Kernel: Linux 7.0.11-76070011-lyraskitty
- GCC: Ubuntu GCC 13.3.0
- Clang: Ubuntu Clang 18.1.3
- Program: 4,096 instruction words, 50,000 executions per engine

Rates are millions of VM instructions per second. Higher is better.

| Build | Workload | Computed goto | `switch` | Function pointer |
|---|---:|---:|---:|---:|
| GCC `-O2` | NOP dispatch | 1,453 | **1,740** | 744 |
| GCC `-O2` | periodic mixed | 645 | 702 | **787** |
| GCC `-O2` | shuffled mixed | 143 | 149 | **167** |
| GCC Release (`-O3`) | NOP dispatch | 1,700 | **1,757** | 780 |
| GCC Release (`-O3`) | periodic mixed | 630 | 655 | **775** |
| GCC Release (`-O3`) | shuffled mixed | 152 | 150 | **168** |
| GCC Release + LTO | NOP dispatch | **1,779** | 1,749 | 933 |
| GCC Release + LTO | periodic mixed | **976** | 757 | 709 |
| GCC Release + LTO | shuffled mixed | **169** | 164 | 167 |
| Clang Release (`-O3`) | NOP dispatch | 1,451 | **1,509** | 989 |
| Clang Release (`-O3`) | periodic mixed | 696 | 693 | **735** |
| Clang Release (`-O3`) | shuffled mixed | 156 | 150 | **166** |

## Initial interpretation

The recollection that TinyVM was fast is supported: all three mechanisms can
execute hundreds of millions of these small VM instructions per second, and
the simplest hot loops exceed one billion per second on this host.

Computed goto is not unconditionally fastest. GCC without LTO favored `switch`
or function pointers on most samples. With GCC LTO, computed goto won every
workload and improved especially strongly on the periodic mixed stream. Clang
was nearly tied between computed goto and `switch`, while function pointers won
its mixed streams.

The next benchmark revision should add repeated randomized engine order,
median/dispersion reporting, CPU affinity, optional performance counters, and
Flowmini-shaped instruction distributions before this evidence guides backend
selection.

## Reproduction

```sh
cmake -S subprojects/TinyVM -B build/tinyvm-bench-gcc-lto \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=gcc \
  -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=ON
cmake --build build/tinyvm-bench-gcc-lto --parallel
build/tinyvm-bench-gcc-lto/tinyvm_dispatch_benchmark \
  --iterations 50000 --words 4096
```
