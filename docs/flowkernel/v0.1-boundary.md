# Flowkernel v0.1 boundary

The initial kernel matrix is intentionally narrow:

```text
read-only kernel access
private temporary filesystem transaction
child-process IPC
local Unix-socket IPC
local-only TCP loopback
child-only user/UTS/IPC namespaces
```

The probes run direct Linux system calls and return a versioned
`flowkernel.probe_report`. They are safe to run on the development host under
ordinary user privileges. Later boundaries require stronger isolation:

```text
IPC/network namespaces → disposable VM
device/ioctl access    → explicitly selected device sandbox
mounts/cgroups/eBPF    → disposable VM with capability policy
```

No probe in v0.1 changes global kernel state, contacts an external network, or
touches host devices.

The corresponding Flowmini capability contract is
`std/abi/kernel.flow`. It declares the 23 libc entry points already exercised
by this probe brick. Flowbind verifies their exact library, C convention,
effect policy, and host symbol availability without executing them. This is a
communication boundary, not permission to perform the operations: execution
and lowering remain subject to capability, provenance, and runtime policy.

All 23 declared kernel entry points now have narrow executable profiles. The
read-only and discovery profiles use bounded buffers; filesystem, IPC, socket,
and namespace profiles use invalid descriptors, null pointers, zero counts, or
non-mutating values where appropriate. Every profile is policy-gated and tested
as a native ELF artifact. This proves the ABI contact boundary, not unrestricted
permission to perform the operations.

The loopback probe may report `skipped` with `EPERM` or `EACCES` when the
containing sandbox forbids network socket creation. This is an infrastructure
limitation, not a successful networking result and not a kernel-probe crash.

The namespace probe uses only a short-lived child and reports an explicit skip
when user namespaces are disabled by host policy.
