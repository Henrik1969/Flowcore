# Flowanalyst analysis-region model

Flowanalyst exposes a bundle-local dependency model in `analysis_regions`.
This is the first substrate for divide-and-conquer semantic analysis.

## Current region kinds

```text
scope:<id>    exported SymbolTable scope
symbol:<id>   exported SymbolTable symbol
target:<name> named target analysis region
```

Each region has:

```json
{
  "id": "target:cli",
  "kind": "target",
  "status": "sane",
  "requires": ["symbol:5", "symbol:6"]
}
```

Region IDs are valid only within the report that contains them. Consumers must
not persist them as global identities.

## Status meaning

`status: sane` means the currently implemented checks found no blocking issue
attached to that region. It does not yet mean that every future semantic rule
has been executed.

`status: rejected` means a blocking diagnostic is attached to the region.

Future versions may add `incomplete`, `blocked`, and `stabilizing` statuses.
Consumers must treat unknown statuses conservatively and display them without
inventing a meaning.

## Dependency meaning

`requires` lists prerequisite region IDs. A consumer may analyze independent
regions concurrently when all their prerequisites are stable. It must not
lower a region unless its transitive prerequisite closure is accepted.

The current graph is deliberately structural. Later semantic passes may add:

- name and type-resolution edges;
- call and data-flow edges;
- ABI and contract edges;
- recursive-cycle/SCC containers;
- fixpoint iteration metadata;
- parallel layer information.

Those additions must preserve the current rule that provenance and diagnostic
identity are independent of execution order.
