# Flowanalyst v0.1 semantic report

Flowanalyst is the independent semantic continuation of the FlowMini frontend:

```text
source -> FlowMini -> flowmini.frontend_bundle -> Flowanalyst
```

It consumes the v2 FlowMini frontend bundle and emits a separate semantic
report. Structural AST and SymbolTable data remain authoritative for the first
stage; semantic diagnostics and facts belong to this report.

## Invocation

```sh
flowmini --dump-frontend-bundle source.flow | Flowanalyst/build/flowanalyst
Flowanalyst/build/flowanalyst bundle.json
```

Exit status is `0` for an `ok` report, `2` when semantic or propagated
frontend diagnostics have error severity, and `1` for invalid input or an
unsupported bundle.

## v0.1 checks

- propagate FlowMini frontend diagnostics;
- detect duplicate names in an exported scope;
- resolve declared type spellings against built-ins and exported type-like
  symbols;
- require exactly one `main` procedure in each named target.

Diagnostics are root-cause records. When a semantic subject is known they carry
the subject symbol, semantic region, AST path, and source coordinates. A future
report revision may add related/cascaded findings; projections should be free to
collapse consequences while retaining the complete machine-readable report.

Targets currently carry an independent regional status (`sane` or `rejected`),
which is the first step toward partial analysis and partial lowering.

The report is intentionally not Graph IR, an optimizer result, a target
artifact, or a replacement for the FlowMini structural bundle.

It may also contain `aggregate_abi_layouts`. These are declarations of
aggregate names and field types discovered in ABI contracts. They are
versioned, inspectable facts with `status: declared` and
`layout_policy: provider_verified_required`; they are not permission to call
the aggregate. Flowbind must keep such calls blocked until provider-side layout
and signature evidence is available.
