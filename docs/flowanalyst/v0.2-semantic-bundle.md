# Flowanalyst semantic bundle contract

This is the planned export boundary for the completed semantic-analysis stage.
It is the input contract for optimizers and later graph/lowering providers.

```text
flowmini.frontend_bundle v2
  → Flowanalyst semantic analysis
  → flowanalyst.semantic_bundle v1
  → optimizer / Graph IR / other consumers
```

The semantic bundle is a derived, immutable snapshot. It does not replace the
original FlowMini bundle and must retain a provenance link to it.

## Required top-level fields

```json
{
  "format": "flowanalyst.semantic_bundle",
  "version": 1,
  "source_frontend": {
    "format": "flowmini.frontend_bundle",
    "version": 2
  },
  "status": "accepted",
  "greenflag": {},
  "semantic_facts": [],
  "diagnostics": [],
  "analysis_graph": {},
  "provenance": {}
}
```

## Statuses

```text
accepted    the complete required semantic closure passed final verification
rejected    one or more blocking semantic findings remain
incomplete  analysis could not establish a required fact
```

Only `accepted` permits ordinary lowering or optimization. Partial consumers
may still inspect or project rejected and incomplete bundles, and a policy may
permit independent accepted targets to proceed when their complete dependency
closures are accepted.

## Green flag

The green flag is a structured proof-of-gate, not a decorative boolean:

```json
{
  "status": "pass",
  "analysis_revision": 1,
  "required_checks": [
    "declaration_legality",
    "name_resolution",
    "type_resolution",
    "dependency_closure",
    "final_integrity"
  ],
  "blocking_diagnostic_count": 0,
  "final_pass": "single_thread_integrity"
}
```

An analyzer must not emit `status: pass` merely because its local region was
successful. The final integrity pass must verify the merged semantic state and
all required dependency closures.

## Semantic fact rules

Facts must be immutable, typed, provenance-backed, and revisioned. A fact may
refer to a bundle-local symbol, scope, AST path, region, or source location.
Fact values must not require consumers to parse human-readable messages.

Examples include:

```text
identifier expression → resolved symbol
type reference        → canonical type identity
call expression       → candidate/selected callable
target                → dependency closure
region                → accepted/rejected/incomplete
```

## Optimizer boundary

The optimizer must consume an accepted semantic bundle. It must not reinterpret
raw source text or bypass Flowanalyst's blocking diagnostics.

Optimizer output should use a distinct versioned format and preserve input
provenance plus transformation provenance. It must not silently overwrite the
original semantic bundle.
