# Flowmini v0.24 Accepted-Language Coverage Matrix

## Purpose and authority

This matrix audits syntax accepted by the executable `parseModule()` frontend
against the explicit raw AST and structural SymbolTable path. Its dimensions
and exit rule are binding for the closed v0.24 line. Row statuses describe the
tagged `flowmini-v0.24-frontend-border` checkpoint. New projection maturation
work belongs to v0.25 and must not rewrite this historical evidence.

A green runtime suite does not prove raw-AST coverage. An AST-only probe does
not prove coverage of syntax accepted by `parseModule()`.

Every canonical construct must have canonical syntax representation, stable
ownership/IDs where cross-reference is required, source provenance, its
intended SymbolTable projection, and focused golden coverage.

## Syntax classification

| Class | Effect on v0.24 gate |
|---|---|
| **Canonical** | Counts against raw-AST and structural-projection completion |
| **Compatibility-only** | Remains on the `parseModule()`/`ModuleSpec` path and does not force Graph IR concepts into the raw AST |
| **Provisional** | Accepted or probed experimentally but cannot define the canonical model until decided |
| **Historical** | Retained as provenance; not an active language requirement |

Legacy direct node, wire, and policy syntax is compatibility-only. Canonical
nodes, ports, wires, and policies belong to Graph IR after the semantic frontend
border, not to v0.24 raw AST.

`print value` is provisional compatibility syntax. Printing is an ordinary
call through a capability/provider function such as `print(value)` or later
`io.print(value)`; it must not create `StatementKind::Print`.

Placement is canonical source meaning. `expr -> ordinary_target` is a
`PlacementStatement` owning a value expression and an `AssignableTarget`.
`expr -> return` is a `ReturnStatement` owning `value_expression`, with
source-form provenance recording arrow placement syntax. Return is control
transfer, not storage, and must never be represented as a fake assignable
target. AST-only `name = expr` and `return expr` probes do not satisfy this
accepted-syntax coverage.

For v0.24, `AssignableTarget` matches currently accepted executable syntax
exactly and is a tagged variant of `IdentifierTarget`, `FieldPathTarget`, or
`IndexedTarget`. It is intentionally not a generic expression target. Future
extensions add explicit target variants rather than making every expression
assignable. Scope, mutability, type compatibility, and assignability are later
semantic-analysis decisions.

The initial payload contract mirrors `parseAssignableTarget()` exactly:

```text
IdentifierTarget
    name
    source location

FieldPathTarget
    base identifier
    ordered field segments, each with source location

IndexedTarget
    base identifier
    one or more index ExpressionIds
```

Index components reference ordinary expressions, but the target remains a
closed l-value-shaped structure.

Statements preserve their source spelling as provenance without changing
semantic ownership:

```text
PlacementStatement
    source_form = ArrowPlacement

ReturnStatement
    source_form = KeywordReturn | ArrowPlacement

AssignmentStatement
    source_form = EqualsAssignment
```

Assignment, placement, and return remain distinct statement forms. Both return
spellings denote control transfer; neither makes `return` an assignable target.

## C5 typed statement direction

`Statement` owns location plus a typed payload variant. Statement kind is
derived from payload type; each payload owns only fields meaningful to that
form:

```text
Statement::Payload = variant<
    LetStatement,
    AssignmentStatement,
    PlacementStatement,
    IfStatement,
    WhileStatement,
    BreakStatement,
    ContinueStatement,
    ReturnStatement,
    ExpressionStatement,
    FlowStatement,
    UnknownStatement
>
```

Generic kind strings, expression-ID arrays, and legacy JSON fields are derived
compatibility projections, never competing semantic state.

Migration checkpoints:

```text
C5a  define typed statement payload structs
C5b  derive StatementKind and JSON compatibility projections
C5c  migrate Let, Assignment, and Return ownership
C5d  migrate If, While, ElseArm, and BlockId ownership
C5e  implement and migrate PlacementStatement
C5f  remove irrelevant optional scaffolding after golden coverage
```

Current implementation checkpoint:

```text
C5a  implemented: all typed payload and AssignableTarget structures exist
C5b  implemented: StatementKind and JSON compatibility fields are derived
C5c  implemented: Let, Assignment, and keyword Return own their data in payloads
C5d  implemented: If/While own conditions and blocks; If owns ElseArm
C5e  implemented: arrow placement and arrow-return preserve exact source form
C5f  implemented: obsolete shared optional statement fields are removed
```

The golden validator checks exact payload shapes and payload/projection
agreement for all emitted statement forms. C5 completion is an implementation
checkpoint, not closure of the v0.24 frontend gate.

## Structural SymbolTable checkpoint

The current eleven-probe projection covers source-unit, import, function,
parameter, record, field, refined type, ABI contract/type/struct/extern, main,
block, and local-let symbols for AST
forms that exist. Symbols carry declaration line/column and factual unresolved
type spellings where applicable. Module symbols carry `source_unit_kind`;
functions carry `return_type_spelling`; parameters, fields, and local lets carry
`declared_type_spelling`; refined types carry `base_type_spelling` and ordered
`invariant_spelling` facts. ABI symbols carry only written `AbiTag` facts. These are
derived projections from raw AST structure, not semantic type identities.

The focused set covers `canonical_type_spelling_probe`, `type_reference_probe`, `statement_else_probe`,
`placement_statement_probe`, `function_signature_gallery`,
`statement_initializer_probe`, `recursive_expression_probe`,
`unit_symbol_projection_gallery`, `refined_contract_probe`, and
`abi_contract_probe`, and `structured_value_probe`. The unit galleries guard `source_unit_kind = unit`,
unresolved refined/field/signature/ABI facts, and the
inspection-versus-execution boundary for units. The recursive probe uses the
canonical `type Point { field ... }` spelling and guards record/field projection
alongside recursive expression ownership. The function gallery also guards that an
absent written return type produces no `return_type_spelling` fact.

The AST does not yet carry its source filename, so the SymbolTable location file
component remains empty and the observable dump renders it as `<source>`. These
eleven goldens prove the bridge and metadata contract across a broader surface,
not full accepted-language coverage.

## v0.24 exit rule

v0.24 completes only when every `parseModule()` form is classified; every
canonical accepted form is represented losslessly; compatibility-only forms
remain isolated from the canonical AST contract; provisional forms have an
explicit canonical/compatibility/historical decision; syntax cannot disappear into skipped tokens or
unknown placeholders; IDs, parentage, references, and provenance validate; the
intended structural projection is complete; focused goldens cover every row;
an independent process can validate the versioned AST/SymbolTable export and
continue into a lowering skeleton without reparsing source; all normal gates
remain green; and current documentation matches the checkout.

Only then may the line advance to v0.25 SymbolTable maturation and later v0.26
semantic analysis.

This exit rule passed on 2026-08-16. The project owner formally declared the
v0.24 raw frontend/export border closed after the independent-consumer and Tier
3 Firetest evidence passed.
