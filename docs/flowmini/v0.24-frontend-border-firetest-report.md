# Flowmini v0.24 Frontend Border Firetest Report

## Tested state

This report records the frontend-bundle checkpoint developed from:

```text
70d1895 Complete Flowmini v0.24 frontend checkpoint
```

The containing commit is the immutable identity for the tested implementation,
consumer, attacks, goldens, and this report. No version, branch, or tag change
is part of the border declaration.

## Border claim under test

An independent process can consume exported raw AST and SymbolTable state and
continue toward lowering without linking Flowmini internals, including Flowmini
headers, and without reparsing source.

The `flowmini.frontend_bundle` v1 envelope carries the AST, generic SymbolTable
snapshot, structural AST origins, source-map provenance, and diagnostics slot.
The standard-library-only Python consumer validates that envelope and emits a
deterministic lowering skeleton containing declarations, blocks, statements,
scopes, symbols, complete typed facts, origins, and resolved source locations.

## Defects exposed and corrected

The attack/review pass found two preservation defects before the final rerun:

1. SymbolTable JSON represented non-finite `double` facts as `null`, losing the
   distinction among NaN and positive or negative infinity. The snapshot now
   uses explicit `nan`, `positive_infinity`, and `negative_infinity` encodings,
   guarded by a SymbolTable unit test and consumer validation.
2. The independent lowering skeleton emitted fact keys but omitted typed fact
   values. It now carries the complete ordered fact objects, and the goldens
   guard their transport.

All Tier 2 and Tier 3 checks were rerun after these corrections.

## Negative attack surface

The permanent gate rejects unsupported bundle and AST versions, a missing
symbol origin, a dangling AST JSON Pointer, an unknown scope parent, an unknown
source-map source, an AST location mapped to generated text, a pool-size
mismatch, a duplicate symbol ID, an invalid typed fact value, and a requested
construct absent from the bundle.

## Verdict and remaining limits

The tested evidence supports the v0.24 frontend-export border claim. The project
owner formally declared the border passed on 2026-08-16.

This does not claim semantic type resolution, identifier-use resolution,
contract validation, Graph IR, or runtime lowering. Numeric IDs are stable
within one exported revision only. LeakSanitizer still needs an untraced local
or CI environment for direct evidence.
