## Defects exposed and corrected

The pressure pass initially found two undefined-behavior defects:

1. TokenTree's unknown-status test constructed an invalid enum value. The
   diagnostic helper now accepts an integer status code while operational APIs
   continue returning `TokenTreeStatus`.
2. The struct-by-value ABI probe called `point_sum` through a function pointer
   whose local C++ carrier type differed from the provider's C carrier. The
   runtime and test provider now share the focused declaration in
   `subprojects/testabi/include/flowmini_testabi.h`.

Both corrected paths pass strict UBSan without suppressions.

## Commands and isolation

Fresh GCC and Clang trees were configured with explicit compilers and Ninja.
Dedicated Clang trees used `-fsanitize=address` and `-fsanitize=undefined`
respectively, with `-fno-omit-frame-pointer`. Each tree ran:

```text
cmake --build <tree> -j20
cmake --build <tree> --target flowmini_ast_golden_tests
cmake --build <tree> --target flowmini_symbol_projection_tests
cmake --build <tree> --target flowmini_suite
ctest --test-dir <tree> --output-on-failure
```

The ABI prerequisite was prepared sequentially for each build because the
legacy provider bridge writes `build/libflowmini_testabi.so`. The normal debug
provider was restored after pressure testing.

## Remaining limitations

- LeakSanitizer needs a non-traced local or CI environment for direct evidence.
- The shared `Point` C header is explicit test-provider compatibility
  infrastructure, not the future general ABI call mechanism.
- Canonical primitive runtime carriers, semantic type resolution, contract
  evaluation, and Graph IR remain later layers and were not claimed by this
  raw-frontend checkpoint.
