# Flowmini v0.24 Frontend Bundle Contract

Authority: frozen version 1 contract for the tagged
`flowmini-v0.24-frontend-border` checkpoint. Active Flowmini v0.25 uses the
[version 2 frontend bundle contract](v0.25-frontend-bundle.md). This document
remains authoritative only for v0.24 producers and consumers.

## Purpose

The frontend bundle is the process boundary between Flowmini's raw frontend and
independent later-stage tools. A consumer must be able to inspect the AST,
scopes, symbols, factual metadata, and structural origins without linking
Flowmini, including Flowmini headers, or reparsing source.

```bash
./flowmini --dump-frontend-bundle examples/ast/type_reference_probe.flow \
    > frontend-bundle.json

python3 tools/consume-flowmini-frontend-bundle.py frontend-bundle.json \
    > lowering-skeleton.json
```

The reference consumer uses only the Python standard library.

## Envelope

```json
{
  "format": "flowmini.frontend_bundle",
  "version": 1,
  "source": { "path": "examples/ast/type_reference_probe.flow" },
  "source_map": {
    "coordinate_space": "expanded_lines",
    "files": [],
    "lines": []
  },
  "ast": { "format": "flowmini.ast.v2" },
  "symbol_table": {
    "format": "symboltable.snapshot",
    "version": 1
  },
  "symbol_origins": [],
  "scope_origins": [],
  "diagnostics": []
}
```

`source.path` preserves the path supplied to the command. Locations inside the
current AST and projection use the expanded lexer line/column coordinate space.
`source_map.files` identifies every root or imported file, while
`source_map.lines` maps each expanded line to its source file ID and original
line. Generated separator lines have explicit null source identity.

The independent consumer requires every nonzero AST and symbol location to map
to non-generated source text. The multi-file `import_demo` gate currently
guards three distinct source files through this contract.

`diagnostics` is reserved in v1 and is currently empty. CLI or structural-build
failure still produces a nonzero exit rather than a partially valid bundle.

## SymbolTable snapshot

`symboltable.snapshot` is a generic, deterministic export owned by SymbolTable.
It contains:

- the global scope ID;
- every scope ID, parent, owner symbol, children, and contained symbols;
- every symbol ID, owning and introduced scopes, kind, visibility, and
  definition state;
- declaration and definition locations;
- ordered factual metadata with an explicit value type.

IDs are stable and unique within one exported frontend revision. v1 does not
claim that numeric IDs remain unchanged after source edits or across unrelated
frontend runs.

The existing human-readable SymbolTable dump remains a diagnostic/golden view;
it is not the inter-process contract.

## Structural origin links

Flowmini owns the AST-to-SymbolTable origin sidecars:

```json
{
  "symbol_id": 7,
  "ast_path": "/declaration_pool/2/parameters/0"
}
```

```json
{
  "scope_id": 4,
  "ast_path": "/block_pool/3"
}
```

Paths are JSON Pointers resolved relative to the embedded `ast` object. They
always target canonical pools or `/source_unit`, never the derived
`source_unit.declarations` compatibility projection.

This supports parent-owned parameters, fields, and ABI members without giving
them artificial global AST IDs. Every projected symbol and every non-global
scope has exactly one structural origin. The global scope has none.

Origins state where projected structure came from. They do not resolve an
identifier use to its declaration, prove type identity, validate a contract, or
perform any other semantic analysis.

## Independent-consumer gate

The `flowmini_frontend_bundle_tests` target exports bundles and invokes the
independent consumer for:

- type references, refined/record declarations, functions, parameters, fields,
  locals, and blocks;
- placement and arrow-return statements;
- equals-assignment statements;
- ABI declarations and nested ABI symbols.
- real multi-file import expansion and original file/line provenance.

The consumer validates formats and versions, pool sizes and IDs, scope/symbol
ownership, fact encodings, locations, and every JSON Pointer before emitting a
deterministic lowering skeleton. The gate also copies only the consumer and a
real multi-file bundle into an isolated temporary directory and proves that the
consumer succeeds there without repository files, Flowmini headers, or source
input.

Eleven negative checks must fail: one requires a nonexistent construct, while ten
attack malformed bundle versions, AST formats, origins, JSON Pointers, scope
ownership, source-map identities, generated-line provenance, pool sizes, and
duplicate symbol IDs, plus typed fact-value encodings.

The skeleton proves transport and structural continuation toward lowering. It
is not Graph IR and does not claim semantic correctness.
