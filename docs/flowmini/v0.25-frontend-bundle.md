# Flowmini v0.25 Frontend Bundle Contract

## Purpose and version boundary

Version 2 hardens the v0.24 process boundary with explicit, typed structural
origin metadata. The embedded raw AST remains `flowmini.ast.v2`, and the generic
SymbolTable export remains `symboltable.snapshot` version 1. Only the Flowmini
bundle envelope and its structural-origin contract advance.

Consumers must reject unsupported bundle or origin-contract versions. The
frozen v0.24 producer remains a version 1 historical checkpoint.

```json
{
  "format": "flowmini.frontend_bundle",
  "version": 2,
  "origin_contract": {
    "format": "flowmini.structural_origins",
    "version": 1
  },
  "ast": { "format": "flowmini.ast.v2" },
  "symbol_table": {
    "format": "symboltable.snapshot",
    "version": 1
  },
  "symbol_origins": [],
  "scope_origins": []
}
```

## Structural origin entry

Each projected symbol and each non-global scope has exactly one origin entry:

```json
{
  "symbol_id": 7,
  "ast_path": "/declaration_pool/2/parameters/0",
  "entity_kind": "parameter",
  "role": "function_parameter",
  "ast_id": null,
  "source_location": { "line": 4, "column": 18 }
}
```

`ast_path` is a JSON Pointer relative to the embedded AST. `entity_kind`
describes the structural target form, while `role` records why that structure
produced the projected entity. `ast_id` contains the canonical arena ID for
declarations, statements, and blocks. Parent-owned source-unit, parameter,
field, and ABI-member structures have `null` IDs rather than invented ones.

`source_location` is expressed in the expanded source coordinate space and must
match both the pointed-to AST structure and the source map. A consumer may
therefore validate provenance without guessing by name.

The global scope deliberately has no AST origin. Origins describe structural
provenance only; they do not resolve identifier uses, normalize type names,
validate legality, or establish semantic identity.

## Consumer obligations

The independent reference consumer rejects bundles when:

- an origin is missing, duplicated, or attached to the global scope;
- a pointer is malformed, noncanonical, unresolved, or resolves to the wrong
  structural kind;
- a role disagrees with the symbol kind, scope kind, parent declaration, or
  owning statement/block relation;
- a canonical AST ID disagrees with the pointer, or a parent-owned entity claims
  an artificial ID;
- an origin location disagrees with the AST target, projected symbol, or source
  map;
- scope ownership and origin ownership disagree.

The emitted lowering skeleton contains complete origins and a reverse
`origin_index`. Independent tools can construct AST-to-symbol and AST-to-scope
lookups from exported data alone.

## Current gate

The active gate covers seven golden source families, one isolated consumer run,
and nineteen required failures. It includes imports, source units, functions,
parameters, records, fields, refined types, local bindings, ABI declarations and
members, main declarations, and function/record/ABI/main/if/else/while scopes.

This contract is sufficient for structural continuation. It is not Graph IR and
does not begin semantic analysis.
