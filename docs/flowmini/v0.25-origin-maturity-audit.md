# Flowmini v0.25 Structural Origin Maturity Audit

## Finding

v0.24 established resolvable structural origins. v0.25 bundle version 2 makes
them explicit, role-correct, provenance-consistent, and independently
verifiable. Every projected symbol and non-global scope has exactly one typed
origin; the global scope has none.

raw syntax. Refined types are represented and audited; a future alias form must
receive an explicit role and test rather than being inferred from this row.

## Scope audit

| Scope | Canonical AST origin | Role | AST ID | Gate |
|---|---|---|---|---|
| Global | none | none | none | consumer invariant |
| Module | `/source_unit` | `module_scope` | none | type/import bundles |
| Function | function declaration | `function_scope` | declaration ID | type/import bundles |
| Record | record declaration | `record_scope` | declaration ID | type bundle |
| ABI | ABI declaration | `abi_scope` | declaration ID | ABI bundle |
| ABI struct | nested ABI struct | `abi_struct_scope` | none | ABI bundle |
| Extern function | nested extern function | `extern_function_scope` | none | ABI bundle |
| Main | main declaration | `main_scope` | declaration ID | type/import bundles |
| Target | target declaration | `target_scope` | declaration ID | type/import bundles |
| If then-block | `/block_pool/{id}` | `if_then_scope` | block ID | else/control-flow bundles |
| Else block | `/block_pool/{id}` | `else_block_scope` | block ID | else bundle |
| While body | `/block_pool/{id}` | `while_body_scope` | block ID | control-flow bundle |

Else-if continuation is represented by the next `IfStatement`; its then and
optional final-else blocks receive their own roles. No artificial “else-if
scope” is introduced.

## Independent validation and attacks

The reference consumer validates pointer resolution, structural kind, role,
canonical ID, source provenance, symbol location, scope ownership, uniqueness,
and the deliberate absence of a global origin. It emits a reverse origin index
without matching names.

Negative attacks include resolvable wrong-kind pointers, wrong roles, missing
origins, duplicate symbol and scope origins, location disagreement, and an
illegal global-scope origin, in addition to the inherited format, ownership,
source-map, pool, and fact-encoding attacks.

## Remaining limits

- Numeric AST, symbol, and scope IDs are stable only within one exported
  revision. Cross-edit persistent identity is not claimed.
- Origins identify declarations and structural scopes, not identifier uses or
  semantic references.
- Type resolution, alias normalization, legality, contracts, and ABI lowering
  remain outside v0.25.
- New projected entity kinds require an explicit origin role, consumer rule,
  positive golden, and wrong-role/wrong-kind attack before they are mature.

## 2026-08-19 closure audit

The implementation audit confirmed that the AST arenas, structural origins,
source-map coordinates, and independent consumer checks agree with the tables
above. One stale field pair was removed from `Parameter`: parameter nodes do
not own bodies, so `has_body` and `body_location` had no producer, consumer, or
serialized meaning. Function and `main` body presence remains represented by
their optional `body` block ID. The serialized `has_body` value is retained as
a compatibility convenience and is derived from that canonical ID.

The projection intentionally remains factual: malformed arena references are
rejected at the frontend-bundle boundary, while semantic resolution,
identifier-use links, and cross-revision identity remain later-stage work.
