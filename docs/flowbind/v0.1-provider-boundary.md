# Flowbind v0.1 provider boundary

Flowanalyst exports ABI requirements as facts rather than making the provider
choice itself. Each requirement contains:

```text
contract, library, convention, symbol, effect
```

Flowbind verifies `library` and `symbol` through the host dynamic loader. It
does not execute code, infer ABI layouts, or lower calls. Therefore:

```text
binding ready ≠ ABI verified ≠ call safe ≠ lowered
```

The first live probe uses `std/abi/libc.flow` and checks `libc.so.6` symbols
such as `strlen`, `abs`, `labs`, and `puts`. The report records that execution
was not performed.

The next boundaries are deliberately separate:

1. provider identity and search policy;
2. ABI signature/layout verification;
3. capability and effect authorization;
4. call lowering;
5. runtime dispatch or direct linkage.
