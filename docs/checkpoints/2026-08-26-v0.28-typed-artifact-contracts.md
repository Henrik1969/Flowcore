# Flowcore v0.28 typed artifact-contract status

**Status:** current experimental implementation  
**Date:** 2026-08-26  
**Branch:** `v25-symboltable-projection`

The active compiler chain now uses one public Flowcontracts boundary for strict
JSON parsing and authority validation from the frontend bundle through lowering.
Flowparallel, Flowoptimize, Flowbind, Flowlower, Flowanalyst, and the adjacent
CUDA/runtime/graph planners no longer select JSON authority through substring
searches.

Implemented and executable:

- complete-input parsing, duplicate-key refusal, exact signed 64-bit integers,
  Unicode strings, JSON-path errors, and deterministic serialization;
- typed format/version/status, source, target, operation, block/control,
  provider, ABI, effect, resource, matrix, and authorization-evidence checks;
- independently invocable `flowvalidate` with stable valid, invalid, blocked,
  and unsupported result classes plus canonical round-tripping;
- profile-free source→frontend→semantic→binding/planning→optimization→LLVM/ELF
  flow, including `flowcat`, `sel`, ncurses, generated bindings, and provider
  fallback gates;
- end-to-end identity preservation and independent mutation-refusal evidence.

Current canonical checkout evidence is 57/57 root CTest tests passing. This is
the complete root suite count; focused Flowmini and subsystem suites retain
their own separately documented counts.

Still future or provisional:

- Canonical Graph IR and revisioned persistent identity storage;
- executable safety profiles, WCET/boundedness proof, certification, and
  self-hosting;
- permanent writable-storage language semantics (`c_pointer(N)` remains tested
  compatibility behavior);
- generalized aggregate ABI and arbitrary CUDA/native lowering.

Flowcore remains experimental and is not production-, security-, or
safety-certified.
